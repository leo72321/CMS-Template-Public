# S3 圖床設定：一個入口完成設定與實際驗證

CMS 是 Astro 靜態網站。B2、R2、AWS S3、Wasabi、DigitalOcean Spaces、Hetzner、Scaleway、Akamai 與其他相容服務統一使用 AWS S3 SDK；**只有一個 GitHub Actions 圖床設定入口**，不會為每個供應商複製工作流程。

## 操作：Actions → 圖床設定｜S3 一站式驗證與套用

GitHub 原生 workflow_dispatch **不能實作供應商改變後即時過濾另一個下拉選單**。因此只保留一個「供應商＋機房」選單，從中選取 `b2-us-west-002`、`r2-standard`、`aws-ap-east-2` 等代碼。程式會自動帶入供應商、Region 及真正的 S3 API Endpoint。

| 欄位 | 說明 |
| --- | --- |
| `endpoint_preset` | 必須選供應商與機房；B2 已包括 `us-west-002`。不在清單時選 `custom` |
| `bucket` | 已存在的儲存桶名稱。留白時嘗試列出可見的 Bucket；只有一個就自動選，若有多個優先沿用網站現有 Bucket，否則要求明確填入 |
| `cdn_url` | 公開網站圖片的完整 HTTPS CDN 前綴；例如 `https://cdn.example.com/file/my-bucket/`。CDN Origin/Rewrite 必須事先建好 |
| `account_id` | 僅 Cloudflare R2 端點預設需要 32 位 Account ID，其他供應商留白 |
| `region`、`endpoint` | **只有 `custom` 才填**。已知供應商會由完整 Endpoint 自動辨認，不用再選第二次供應商 |
| `runner` | 正常選 `github-hosted`；額度不足時可手動選 `self-hosted`，只影響當次 |

**金鑰不在表單輸入。** 到私人網站倉庫 `Settings → Secrets and variables → Actions`，建立：
- `S3_ACCESS_KEY_ID`：S3 Access Key ID（B2 的 Application Key ID）。
- `S3_SECRET_ACCESS_KEY`：S3 Secret Access Key（B2 的一般 Application Key，**不能用 Master Key**）。

> S3 Endpoint 是連 API 的地址；CDN URL 是使用者瀏覽器讀取圖片的地址。兩者不能混為一談；填入 CDN URL 也不會自動建立 CDN 或 DNS。

## 按下 Run workflow 會做什麼？

1. 用 GitHub Secrets 連線 S3；嘗試 `ListBuckets`。**某些單桶金鑰沒有列桶權限，不代表無法存取指定 Bucket**。若無法列出但知道 Bucket，仍繼續實測讀寫。
2. 選好桶後先驗證既有媒體遷移限制，避免覆寫已發布圖片的 Bucket 或對外路徑。
3. 實際將少量固定內容的測試檔上傳到 `<網站網域>/.cms-healthcheck/`，以 S3 PutObject 的成功回應作為儲存驗收，不發送 GetObject。
4. 以**未登入、無簽章**的 CDN 公開 URL 發送一次 HTTP HEAD，檢查連結是否正常；不下載內容、不計算下載後雜湊。嘗試查詢 Bucket ACL，能查到才標示公開／私有，否則明確顯示無法判定。
5. 上傳及 HEAD 通過才寫入 `site.config.json`、執行網站完整驗收，最後提交經驗證的設定到 `main`。任一步驟失敗就不提交設定。

測試檔使用固定且可重複的檔名，避免每按一次就增加大量物件；只取得 CDN 回應標頭，不下載檔案內容。**不需要刪除權限，不擅自刪遠端資料。** GitHub Actions 執行摘要會顯示實測結果，不會印出私密金鑰。

## 公有與私有 Bucket 差在哪？

- **公有 Bucket＋公開 CDN**：適合一般 Blog 封面、內文圖片。還是要有寫入金鑰，公開只表示允許讀取。
- **私有 Bucket＋公開網站圖片**：可以，但要先配置有權限的 CDN Origin、Cloudflare Worker 或其他代理。物件來源仍私有，網站圖片的 CDN URL 則能公開讀到，測試才會通過。
- **私有 Bucket＋只有授權讀者能下載的檔案**：需要登入／權限管理或具時效的簽章網址。**現有靜態文章媒體流程尚未支援這個模式**；不能把一次性的簽章 URL 寫死在文章或 Sitemap 裡。

ACL 顯示私有，不保證 CDN 私有；**是否能匿名 HEAD 連到網站 CDN，是另一個獨立檢查**。有些供應商不支援 GetBucketAcl，這時不推測 Bucket 是公有或私有。設定流程**不會擅自把私桶改公桶，也不會在失敗時跳過 CDN 驗證**。

## 歷史網站保護

原本採 B2 Native API 的網站，在你明確執行此新設定且測試全數通過前，會保留原流程。既有 `manifest.json` 有媒體收據時，禁止偷偷改 Bucket、來源服務、Endpoint 或已公開圖片前綴。

現有儲存路徑仍依網站設定；若要改成「網域／site|blog|CPT／UID／檔案」、單尺寸 WebP 或自訂文章類型，必須當成另外的資料模型遷移，不應混在此連線修復裡。
