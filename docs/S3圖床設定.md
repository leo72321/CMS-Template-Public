# S3 圖床設定精靈：B2、R2、AWS S3 與其他雲端

CMS 仍是 **完全靜態 Astro 網站**；S3 僅用於文章媒體上傳，不在訪客瀏覽時執行雲端 SDK。上傳時產生 WebP、CDN 實際讀回比對 SHA-256，通過才把 URL 與尺寸寫入 Markdown／manifest。S3 相容服務共用 AWS SDK，不另外自研協議。

## 從 GitHub Actions 用下拉選單設定

進入你自己的網站倉庫（不要直接在公開模板操作）：

**Actions → 圖床設定精靈 → Run workflow**

一個表單就能完成設定，**不用再查、手填 S3 Endpoint**：

| 欄位 | 一般情況怎麼填 |
| --- | --- |
| `endpoint_preset` **下拉選單** | 選擇「儲存商＋Bucket 機房」，例如 `b2-us-west-004`、`aws-ap-east-2`（AWS 台灣）或 `do-sgp1`（DigitalOcean 新加坡） |
| `bucket` | 已建立的 Bucket／Space 名稱 |
| `cdn_url` | 完整公開 CDN HTTPS URL 前綴，例如 `https://cdn.holeboom.com/file/wordpress-cdn/` |
| `account_id` | 只有選 R2 預設時，必填 Cloudflare 32 位 Account ID |
| `custom_provider`、`region`、`endpoint` | **只有選 `custom` 才需要**；不在選單中的機房可以自己填 |

### 已內建 32 組 Endpoint 預設

| 供應商 | 下拉選單舉例（實際值） | 自動設定 |
| --- | --- | --- |
| Backblaze B2 | `b2-us-west-001`／`b2-us-west-004`／`b2-us-east-005`／`b2-eu-central-003` | `https://s3.<region>.backblazeb2.com` |
| Cloudflare R2 | `r2-standard`／`r2-eu`／`r2-us`／`r2-fedramp` | 根據 Account ID 產生對應 Jurisdiction URL，Region 自動 `auto` |
| AWS S3 | `aws-ap-east-2`（台灣）／`aws-ap-northeast-1`（東京）／`aws-ap-southeast-1`（新加坡）／`aws-ap-east-1`（香港）等 | `https://s3.<region>.amazonaws.com` |
| Wasabi | `wasabi-ap-northeast-1`／`wasabi-ap-southeast-1`／`wasabi-us-east-1`／`wasabi-eu-central-1` | 依官方 Region S3 Endpoint |
| DigitalOcean Spaces | `do-sgp1`／`do-nyc3`／`do-ams3`／`do-fra1` | `https://<region>.digitaloceanspaces.com` |
| Hetzner | `hetzner-fsn1`／`hetzner-nbg1`／`hetzner-hel1` | `https://<region>.your-objectstorage.com` |
| Scaleway | `scaleway-fr-par`／`scaleway-nl-ams`／`scaleway-pl-waw`／`scaleway-it-mil` | `https://s3.<region>.scw.cloud` |
| Akamai／Linode | `akamai-us-east`／`akamai-us-lax`／`akamai-jp-tyo-3` | 依官方 Endpoint（機房代碼與主機名稱可能不同） |
| 特殊機房、其他 S3 | `custom` | 自選供應商並手動填 Region、Endpoint |

**注意 B2：** 必須在 B2 的 Bucket 詳細資訊確認真正的 S3 Endpoint。如果你所在帳號是其他 `us-west-###`／`eu-central-###`，請直接選 `custom`；選錯機房會使上傳失敗。公版不擅自猜你實際的 Bucket 區域。

**注意 R2：** 一般／EU／US／FedRAMP 的 Endpoint 有別；`r2-eu` 等選項會依 Account ID 自動組合，已知 Region 一律使用 `auto`。特殊 R2 端點也可以選 `custom`。

GitHub Actions 原生下拉選單**不能依前一欄即時動態篩選**，所以把供應商與機房合併成同一份選單，一次選對。官方以後新增機房或提供專屬 Endpoint 時，`custom` 永遠保留；不會假裝能自動辨識每個使用者的 Bucket 所在位置。

所選代碼只記錄非機密的 `storage.provider`、`storage.endpoint`、`storage.region`；真正上傳都走統一 AWS S3 相容 SDK。這個下拉選單**不會自動驗證 Bucket 真實存在**，仍須執行後面的連線測試。

### CDN URL 與 S3 Endpoint 不是同一個東西

假設：

- Bucket：`wordpress-cdn`
- CMS 網域：`holeboom.com`
- S3 Endpoint：`https://s3.us-west-004.backblazeb2.com`
- 在設定精靈輸入完整 CDN URL 前綴：`https://cdn.holeboom.com/file/wordpress-cdn/`

CMS 將新增圖片物件寫入 Bucket 的 Key `holeboom.com/iso-security/文章名/cover-abc.webp`，文章使用公開圖片 URL：

`https://cdn.holeboom.com/file/wordpress-cdn/holeboom.com/iso-security/文章名/cover-abc.webp`

**精靈不會自動幫你建立 DNS、CDN Origin、Bucket 公開讀取或 URL Rewrite**；你必須先在儲存服務與 CDN 設定好，確保公開 URL 能對應該 Bucket 的同一個物件。如果使用不同 CDN 服務的完整網址或子路徑，一樣可以填；不強迫 `cdn.<網站網域>`。

一旦 `content/media/manifest.json` 已經有上傳收據，精靈會阻擋變更 Bucket、不同儲存服務、不同 Endpoint 或改變已存在的公開網址前綴，避免整站圖片失效。**若從舊 B2 Native 切換同一個 B2 Bucket 的 S3 協議，且實際產生的 CDN URL 完全相同，則允許切換；但仍需測試 CDN。**

## API Key：只存放 GitHub Secrets

進入自己的網站倉庫 **Settings → Secrets and variables → Actions → New repository secret**：

| Secret | 值 |
| --- | --- |
| `S3_ACCESS_KEY_ID` | 該供應商產生的 S3 Access Key ID（B2 為 Application Key ID） |
| `S3_SECRET_ACCESS_KEY` | 該供應商的 S3 Secret Access Key（B2 為 Application Key） |

B2 的 S3 協議**不能使用 Master Application Key**；請建立可操作指定 Bucket 的一般 Application Key。R2 需要使用 R2 相容 API 所產生的 Access Key ID／Secret Access Key；不要把 Cloudflare 一般 API Token 當成 Secret Access Key。

**不要把金鑰填進 GitHub Actions 的端點預設／手動 Endpoint／CDN 表單**，也不要寫進 `site.config.json`、文章或公開 GitHub Repo。

## 實際連線測試（必須在你的網站倉庫執行）

**Actions → 圖床連線測試 → Run workflow**。

流程為：使用 Secrets 對 S3 Endpoint `PutObject` 上傳固定小檔 → 依 `cdn_url` 生成公開 URL → 從 CDN 讀回檔案 → 比對 SHA-256。通過才顯示成功。測試失敗時不會誤判已可發布；可能是 API 金鑰、Bucket、Region、Origin、CDN URL 路徑或公開讀取權限不正確。

若在本機透過 `npm run media:add` 上傳圖片，需同樣把兩組金鑰填入本機 `.env`；GitHub Secrets 不會自動注入你的 Windows／Debian／Hermes 本機執行環境。舊站尚未切換前，仍保留原 B2 Native 金鑰與上傳方式。

## 初始化全新網站

從公開 CMS Template 建立自己的倉庫後，使用 **Actions → 網站初始化精靈**；這個精靈使用同一份「供應商＋機房」端點預設下拉選單，另有完整 CDN URL、Bucket、網域、名稱和作者等欄位，。無論是初始化或日後改圖床，都不會把私密金鑰存入 Git。
