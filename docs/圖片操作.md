# 圖片操作

給圖片路徑、文章 ID 與替代文字，工具會縮圖、上傳並填回文章。

## 第一次設定

複製 `.env.example` 成 `.env`，填本機設定，不提交 GitHub。

| 環境變數 | 中文意思 |
| --- | --- |
| `B2_APPLICATION_KEY_ID` | B2 應用程式金鑰 ID |
| `B2_APPLICATION_KEY` | B2 應用程式金鑰 |
| `B2_BUCKET_ID` | 儲存桶 ID，不是桶名 |

B2 原生 v4 介面需要 `writeFiles`（上傳）權限。多站可在 Hermes 共用同組環境變數。`media.bucket` 必須與桶 ID 對應；CDN 需能讀到公開圖片。

## 封面

先設定自己的網域，再執行：

```bash
npm run media:add -- --uid 範例新增文章 --file "D:/圖片/cover.png" --alt "文章與分類的關係" --cover
```

產生最大寬度 480、960、1440 的 WebP，小圖不放大；另產生 1200 × 630 的分享圖片。成功後自動寫入 `cover` 的網址、替代文字、寬高與各尺寸。

## 內文

先在內文放唯一占位符：

```markdown
<!-- 圖片:流程圖 -->
```

再執行：

```bash
npm run media:add -- --uid 範例新增文章 --file "D:/圖片/流程.png" --alt "從寫作到發布的流程" --name 流程圖
```

成功後換成 Markdown 圖片，建置時補上寬高、自適應尺寸與延遲載入。封面可重跑覆換；內文重插時，先將原圖片換回占位符。

加 `--dry-run`（預覽模式）只列出處理結果與目標網址，不上傳、不改文章、不需金鑰。

## 上傳成功的定義

每張圖需經過 B2 名稱、大小與 SHA-1（內容校驗碼）確認，再從 CDN 下載比對。全部成功才改文章及 `content/media/manifest.json`。

若 B2 上傳後 CDN 尚未可讀，文章保持原狀。修好後可重跑；失敗過程可能留下未引用物件或同名版本，工具不會擅自刪除。

檔名含內容雜湊。CDN 必須保留原始位元組，不可在同一路徑自動轉檔，否則校驗會失敗。

發布前執行 `npm run media:verify`。不需 B2 金鑰，會確認公開內容使用的 CDN 圖片仍可讀且一致，GitHub 驗收也會執行。

固定素材也可放 `public/`，以 `/圖片.webp` 引用。Markdown 圖片仍需替代文字，建置時會讀本機尺寸。一般文章圖片建議走 B2。
