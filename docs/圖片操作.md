# 圖片操作

給圖片路徑、文章 ID 與替代文字，工具會縮圖、上傳並填回文章。

## 第一次設定

先完成 [網站基本資料初始化](初始化精靈.md)；再從唯一的 **Actions → 圖床設定｜S3 一站式驗證與套用** 選供應商＋機房、Bucket 及完整 CDN HTTPS 前綴。Run 會先測試 S3 上傳，再對 CDN 做一次匿名 HEAD 連結檢查（不下載檔案），才決定是否套用設定。詳見 [圖床設定操作](S3圖床設定.md)。

複製 `.env.example` 為本機 `.env`，填入金鑰：

| 本機變數 | 用途 |
| --- | --- |
| `S3_ACCESS_KEY_ID` | S3 金鑰 ID；B2 對應 Application Key ID |
| `S3_SECRET_ACCESS_KEY` | S3 私密金鑰；B2 對應 Application Key |

如果要在 GitHub 按鈕測試 B2／S3，則把同名金鑰放在 **私人倉庫**的 GitHub Actions Secrets，千萬不要填進表單或 JSON。請參考 [一站式圖床設定與連線驗收](初始化精靈.md)。

未經新版初始化的既有 B2 Native 網站仍可用 `B2_APPLICATION_KEY_ID`、`B2_APPLICATION_KEY`、`B2_BUCKET_ID`，不會被強制遷移。

**CDN URL（完整前綴，例如 `https://cdn.網域/file/桶名/`）必須把公開網址下的 `網域/...` 映射到 Bucket 內 `網域/...` 的同一物件**；單純填子網域不會自動設好 Origin 或公開讀取權限。

## 封面

先設定自己的網域，再執行：

```bash
npm run media:add -- --uid 範例新增文章 --file "D:/圖片/cover.png" --alt "文章與分類的關係" --cover
```

產生最大寬度 480、960、1440 的 WebP，小圖不放大；另產生 1200 × 630 的分享圖片。成功後自動寫入 `cover` 的網址、替代文字、寬高與各尺寸。

## 內文

先在內文放唯一占位符：

```markdown
<!-- 圖片:流程圖 -->
```

再執行：

```bash
npm run media:add -- --uid 範例新增文章 --file "D:/圖片/流程.png" --alt "從寫作到發布的流程" --name 流程圖
```

成功後換成 Markdown 圖片，建置時補上寬高、自適應尺寸與延遲載入。封面可重跑覆換；內文重插時，先將原圖片換回占位符。

加 `--dry-run`（預覽模式）只列出處理結果與目標網址，不上傳、不改文章、不需金鑰。

## 上傳成功與連結檢查

圖片轉檔後交給 B2 Native 或 S3 上傳 API。**API 明確成功後，只對這次上傳的圖片網址發出一次 HTTP HEAD**，確認連結是 2xx，且回應標頭沒有顯示 HTML 假圖片或空檔案。不使用 GET 下載媒體內容，不計算下載後雜湊，也不對同一張圖連續重試。若 HEAD 回 404／403／405 或不正確的類型，就顯示錯誤並暫停更新文章，請檢查 CDN 設定。

B2 Native API 的 SHA-1 是該 API 上傳所需的原生校驗欄位，與重新下載檔案無關；媒體 manifest 仍保留現有 SHA-1、尺寸、時間等欄位，確保既有資料相容。S3 API 接收上傳成功回應後不額外 GET 檔案。內容雜湊仍可用於避免圖片同名與快取衝突。

**正常 CI 只驗證程式、內容與媒體索引，不連線下載或重新 HEAD 已上傳圖片。** 不排程每週巡檢，也不額外消耗 CDN 圖片流量。

需要手動查死圖時，才執行：

```bash
npm run media:verify              # 對目前使用中的遠端連結逐一 HEAD
npm run media:verify -- --batch-size 1000  # 手動分批 HEAD
```

上面不下載媒體內容；此處僅檢查 HTTP 可達性和已提供的回應類型，**不能保證檔案內部每個位元組都正確或圖片一定能成功解碼**。真正發現異常時再另外人工查看。

## 大型網站的媒體成本

- `content/media/manifest.json` 保留圖片尺寸、URL 和上傳收據，圖片本體仍在 B2／S3。
- 媒體索引使用 URL → 資料的 Map，避免每篇文章重複掃描整份媒體清單。
- 已有圖片平時不做遠端掃描、不另加週期性 GitHub Runner 成本。
- `npm run media:orphans` 只輸出未使用檔案候選清單，**不會自動刪除遠端圖片**。
- 既有 B2 Native 與新版 S3 仍共存；已經公開的圖片網址不會因為此驗證調整而改變。
