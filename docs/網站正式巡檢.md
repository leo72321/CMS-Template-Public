# CMS 正式站巡檢：Actions 設計與操作

## 1. 巡檢層次

1. **衍生網站程式碼驗收**：各私有網站原有 GitHub Actions 於 push / PR 執行 npm run docs:check 與 npm run verify，檢查靜態產物的頁面、站內連結、結構和本地圖片。中央巡檢不取代它。
2. **公版 PR 快速測試**：本儲存庫在相關程式碼修改時，以本機 HTTP 模擬站驗證 404、死圖、srcset 與「圖片網址返回 200 但內容是 HTML」。PR 不大量爬正式網站。
3. **正式站 HTTP／媒體巡檢**：每日約台灣時間 06:20，對已啟用網站從 Sitemap 與站內連結爬行，檢查頁面、外部連結、圖片內容與 CSS 資源。
4. **追蹤故障**：保存每站 JSON 與 Markdown 報告七天，在 Actions Summary 彙總；每站故障只開一張 Issue，問題變動才更新，復原時自動結案。

## 2. 網域清單

編輯 config/live-audit-sites.json。state=live 為每日例行巡檢；state=pending 不納入日常巡檢，但可手動指定。是否正式上線不能僅靠 indexable/noindex，因為有些搬站驗收中的公開站仍設定 noindex。

每日預設巡檢：holeboom.com、bittah.tw、banknote.tw、chifeng.com.tw、moaicar.com、dian7la.com。其餘已建立的九個 CMS 儲存庫先列 pending，不會把尚未部署模板的 404 當成正式站故障。

## 3. 手動執行

前往 GitHub → CMS-Template-Public → Actions → CMS 正式站巡檢 → Run workflow，填入 site：

- all：只檢查 live 站。
- all-configured：檢查全部十五個站；pending 如未部署可能失敗，但不會開自動追蹤 Issue。
- 單一網域，例如 bittah.tw：只檢查指定站。

使用公開公版的標準 GitHub-hosted ubuntu-latest 執行，不占用私有衍生站 Actions 額度或自架 Runner 磁碟；最多三站同時掃描。各站的 maxPages、媒體、站外連結數量和時間皆有限制。

## 4. 檢查結論

- **error**：頁面或資源 404／410／5xx、圖片返回 HTML 或無法辨識檔案格式、站外明確 404／410、Sitemap 錯誤。
- **warning**：第三方網站 403／429、防爬、臨時網路異常及 SEO 警告等；保留來源但不直接誤報為確定死鏈。
- **truncated**：掃描達到頁面／資源／外部連結／時間上限，不會假裝「全站通過」，需要調高限制或拆分掃描。

圖片以 GET + Range 取樣並驗證檔案開頭，不只靠 HEAD 的 200 判定；請求有重試、超時與禁止掃描內網目標的保護。流程只讀，不會上傳圖片或寫入 B2。

## 5. 範圍界線與修復

本工具驗證 HTTP、靜態 DOM 引用及圖片回應內容，**不等於逐頁真實瀏覽器視覺驗收**：CSS 可取得不代表版型正確，圖片檔頭正常也不證明整張完整解碼。視覺回歸、互動、RWD 要另搭配瀏覽器抽測。

故障不應自動刪連結、刪文章、盲目改成首頁 301，或覆蓋原始 WordPress B2 圖片。由報告找出「來源頁→失效資源」，確認正確目標後再透過對應網站 PR 修復、部署並重新驗證。報告與 Issue 在公開公版庫，請勿將帶 token 的私密 URL 放在公開網站。

新網站先加 pending，正式部署完成再改成 live；每次新增站點只需更新登錄表，無須手改 Actions matrix。
