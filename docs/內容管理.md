# 文章與頁面怎麼管

先看 [網站結構總覽](SITE_STRUCTURE.md)，再開對應內容。Markdown 上方兩條 `---` 之間是欄位，下面是正文。

```yaml
---
uid: 我的文章
title: 我的第一篇文章
description: 這篇文章的閱讀摘要。
slug: 我的第一篇
category: 網站筆記
tags:
  - 內容管理
topic: 網站入門
publishedAt: '2026-10-21'
draft: true
sample: false
---
```

| 欄位 | 中文意思 | 規則 |
| --- | --- | --- |
| `uid` | 永久內容識別碼 | 全站唯一，不隨標題改動 |
| `title` | 標題 | 自動成為頁面唯一 H1 |
| `description` | SEO 簡介 | 必填，不留白 |
| `slug` | 固定網址名稱 | 中英文皆可，不含斜線、空白、點號 |
| `category` | 分類 ID | 選一個既有分類 |
| `tags` | 標籤 ID 清單 | 選既有標籤，可留空陣列 |
| `topic` | 主題群集 ID | 選填，與分類、標籤不同 |
| `publishedAt` | 發布日期 | 台灣日期 `YYYY-MM-DD` |
| `updatedAt` | 內容實質更新日期 | 選填，不早於發布日 |
| `draft` | 是否草稿 | 預設 `true`，完成才改 `false` |
| `noindex` | 是否不收錄 | 預設 `false` |
| `sample` | 是否範例 | `true` 永遠不收錄，正式內容改 `false` |
| `aliases` | 舊網址清單 | 自動產生 301 永久轉址 |
| `cover` | 封面資料 | 由圖片工具自動填入 |

Page（獨立頁面）不使用分類、標籤、主題與文章日期。首頁、頁首與頁尾直接在 `.astro` 修改。正文從 `##` 開始，避免重複 H1。

## 分類、標籤與主題

分類及標籤放在各自資料夾的 JSON 檔：

```json
{
  "id": "新分類",
  "slug": "新分類",
  "name": "新分類名稱",
  "description": "這個分類的導讀說明。",
  "indexable": false
}
```

`id` 是文章引用 ID；`slug` 是網址；`name` 是顯示名稱；`description` 是導讀；`indexable` 是是否允許收錄。即使設成 `true`，仍需達最低文章數與有導讀。

主題放在 `content/topics/`：

```json
{
  "id": "網站入門",
  "name": "網站入門指南",
  "description": "從內容到發布。",
  "hub": "入門指南"
}
```

`hub` 是中心文章或獨立頁面的 `uid`。主題沿用該中心頁網址，不額外創造一層目錄。子文章連回中心，中心列出子文章。子文章公開前，中心頁也要公開。

相關文章依主題、共同標籤、相同分類加權，每次建置重算。正文連結仍由編輯決定，不會把所有關鍵字換成連結。

## 改網址與刪文

改標題不用改 `slug`。需要改網址或刪文時，在替代目標加入舊網址：

```yaml
aliases:
  - /原分類/原文章網址/
```

再跑 `npm run urls:update`。缺轉址就會失敗，既有轉址不能遺失，也不建立轉址鏈。

分類、標籤改網址時，也要在該 JSON 設定加上 `aliases` 舊網址陣列。文章原網址需各自保存，分類彙整頁與標籤彙整頁的網址也受到保護。

## 日期與範例

尚未到台灣發布日的文章不輸出。靜態網站不會在午夜自行更新，日期到達後必須重建；公版不預設排程。

新站尚未上線、內容全部仍是公版範例時，Agent 可一次清理範例與範例網址紀錄，再跑完整驗收。這個例外不能用在已公開正式網址。
