# GitHub 與 Cloudflare Pages

每站一個獨立倉庫、一個 Pages 專案。公版更新不會自動同步舊站。

## 公版設定

GitHub 的 Settings（設定）→ General（一般）啟用 Template repository（範本倉庫），之後使用 Use this template（使用此範本）。私有公版產生新倉庫時，也請選 Private（私有）。

倉庫的程式碼寫入權限，與建立倉庫、修改範本設定的管理權限不同。連接工具不一定全部支援。

## Pages 建置設定

在 Cloudflare Pages 的「連接 Git」流程選新倉庫：

| 設定 | 內容 |
| --- | --- |
| Production branch（正式分支） | `main` |
| Framework preset（框架） | Astro 或 None（無） |
| Build command（建置指令） | `npm run build` |
| Build output directory（輸出目錄） | `dist` |
| Root directory（根目錄） | 留空 |
| Node.js version（執行環境） | 24，已附 `.nvmrc` |

純靜態輸出，不需伺服器轉接器、資料庫或 B2 上傳金鑰。產物內含 Pages 可用的 `_headers` 與 `_redirects`。

Cloudflare 介面若優先顯示 Workers（另一種部署服務），請選原定的 Pages 流程；此公版保持靜態 Pages 輸出。

接上正式網域後，確認網站 `domain` 一致，正式分支與 `productionBranch` 一致。Pages 的 `CF_PAGES`、`CF_PAGES_BRANCH` 會用來判斷預覽索引保護。

正式文案、範例與導覽完成，再開 `indexable: true`。這份公版不會移動或部署既有網站。

## PR 與驗收

GitHub Actions（自動檢查）會確認結構表已更新，檢查型別、測試、建置、SEO、效能與 CDN 圖片，並保存中文報表附件。

建議把「內容、SEO 與效能檢查」設為合併必要檢查，透過功能分支與 PR 更新。分支保護是倉庫管理設定，工作流程檔不會自行啟用。

PR 預覽成功不等於正式部署完成。正式驗收還要確認網域、HTTP 狀態、索引標頭、分享圖片與追蹤。
