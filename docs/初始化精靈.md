# 網站初始化與 S3 圖床設定

GitHub Actions 原生表單不支援供應商選擇後動態篩選下一欄，因此不設九個重複的圖床設定工作流程。現在統一為**一個 S3 設定入口**，選單直接包含供應商＋機房。

## 第一步：建立網站基本資料

使用 [公開 CMS 模板](https://github.com/leo72321/CMS-Template-Public) 建立自己的私人倉庫。

進入 **Actions → 網站初始化精靈（基本資料） → Run workflow**，輸入網域（不含 https）、站名、網站簡介與作者，驗證後提交基本設定。

## 第二步：填 S3 與 CDN

在私人倉庫 **Settings → Secrets and variables → Actions** 建立兩個 Secrets：

| Secret | 值 |
| --- | --- |
| `S3_ACCESS_KEY_ID` | S3 金鑰 ID（B2 一般 Application Key ID） |
| `S3_SECRET_ACCESS_KEY` | S3 私密金鑰（B2 一般 Application Key，不能用 Master Key） |

回到 **Actions → 圖床設定｜S3 一站式驗證與套用 → Run workflow**：

1. `endpoint_preset` 下拉選「供應商＋機房」，例如 `b2-us-west-002`。只有特殊機房才選 `custom` 並手動填 `region`、`endpoint`。
2. `bucket` 可填實際 Bucket 名稱，也可留白嘗試自動辨識；若金鑰沒有列桶權限、且無法判定唯一桶，須明確填入。
3. `cdn_url` 必填完整公開 HTTPS CDN 前綴（例如 `https://cdn.example.com/file/wordpress-cdn/`）。Cloudflare R2 預設端點要另外填 32 位 `account_id`。
4. 按 Run：先驗證實際 S3 讀寫，再從 CDN 以匿名方式讀回比對 SHA-256。**成功才提交網站圖床設定**。

**請注意：** 此流程不會替你創建 Bucket、修改公開／私有權限、設定 DNS 或 CDN Origin。私有 Bucket 要服務公開網站圖片，需要先有能授權讀取的 CDN/Worker；完全私密附件需要另一套登入或簽章授權機制，現有公開文章不適用。

不要把金鑰貼在任何 workflow 表單、文章、程式碼、公開倉庫或聊天裡。詳見 [S3 圖床設定](S3圖床設定.md)。
