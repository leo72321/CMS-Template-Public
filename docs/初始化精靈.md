# GitHub 中文網站初始化精靈：S3 / B2 / R2

## 1. 先複製私人網站

1. 在 [CMS-Template-Public](https://github.com/leo72321/CMS-Template-Public) 點 **Use this template（使用此範本）→ Create a new repository（建立倉庫）**，選 **Private（私人）**。
2. 進入新倉庫 **Actions（動作）→ 網站初始化精靈 → Run workflow（執行工作流程）**，選 `main`。
3. 填入網站名稱、正式網域、網站簡介、作者、**儲存服務下拉、Region、Bucket、完整 CDN HTTPS URL（可有路徑）**；Endpoint 通常可留空由系統推算，Akamai／Other S3 必填，R2 可另填 Account ID。**表單不收集 API 金鑰。**
4. 執行通過後，工作流程會驗證設定、重新產生內容索引及執行網站測試，最後將 `site.config.json` 等設定提交到你的私人倉庫。

> **注意：** 這個動作不會幫你註冊網域、建立 B2 儲存桶、設定 DNS 或自動連接 Cloudflare Pages。

## 2. 使用 Backblaze B2 測試

| 欄位 | 填寫範例 |
| --- | --- |
| 圖片儲存方式 | `b2` |
| S3 API 端點（選填） | 留空就使用 `https://s3.us-west-004.backblazeb2.com` |
| Region（區域） | `us-west-004` |
| Bucket（儲存桶名稱） | `my-media`（填你的實際桶名） |
| CDN 完整 URL | `https://cdn.example.com/file/my-media/`（填自己實際的公開前綴） |

B2 請建立 **S3 相容 Application Key**；Key ID 是 Access Key ID，Application Key 是 Secret Access Key。必須授權對應儲存桶的上傳權限。不要把金鑰放在表單、Markdown、JSON 或程式碼內。

進入私人倉庫 **Settings → Secrets and variables → Actions → New repository secret**，新增：

- `S3_ACCESS_KEY_ID`：你的 B2 Key ID。
- `S3_SECRET_ACCESS_KEY`：你的 B2 Application Key。

Cloudflare R2 改選 `r2`，Region 留空為 `auto`，再填 32 字元 Account ID（或手填 Endpoint）。另有 Wasabi、DigitalOcean Spaces、Hetzner、Scaleway、Akamai 和 Other S3 選單；共用 S3 上傳程式。完整說明見 [S3 圖床設定](S3圖床設定.md)。

## 3. CDN 子網域必須真的能讀到物件

假設網站網域為 `example.com`，你在 CDN URL 欄位填 `https://cdn.example.com/`，物件實際存放在：

`Bucket: my-media`

`Key: example.com/blog/文章名稱/cover.webp`

CMS 產生的對外圖片網址就是：

`https://cdn.example.com/example.com/blog/文章名稱/cover.webp`

**填入 CDN 完整 URL 並不會自動建立代理，也不是把 DNS CNAME 指到 S3 API 端點就一定能讀取。**

你需要先在 Cloudflare 設定可公開讀取的 CDN Origin（來源站）及必要的 URL Rewrite（路徑改寫）。若使用 B2 原生公開下載來源，來源實際路徑通常含有 `/file/<儲存桶名稱>/`；CDN 需將上述公開網址映射到正確的 B2 檔案下載網址。若儲存桶不公開，就需要自行配置具備適當權限的讀取代理。

CDN 必須原樣回傳物件位元組，不可替相同圖片網址自動轉檔，否則內容雜湊校驗會失敗。

## 4. 按鈕測試 S3 實際上傳及 CDN 讀取

在你的**私人倉庫**進入：

**Actions → 圖床連線測試 → Run workflow（執行工作流程）**

系統會使用前述兩組 GitHub Secrets，透過 S3 PutObject 上傳一個小型固定測試檔，接著從 CDN 子網域下載並比對 SHA-256 雜湊。

- 成功：代表該次 S3 寫入與 CDN 讀回已通過。
- 失敗：請檢查 S3 端點、金鑰授權、儲存桶、CDN Origin 和 DNS。
- 沒有金鑰：會直接停止，不會假裝成功。

此測試檔可重複使用同一個路徑，避免每次測試留下不同檔案。**本工作流程不會讀取或公開 Secrets 的值。**

## 5. 發布與後續上傳圖片

將私人倉庫連接 Cloudflare Pages，選擇 `main`，建置命令 `npm run build`，輸出目錄 `dist`。這是獨立的建站步驟。

圖片 CLI 使用 `npm run media:add`；新站已設定 `storage` 時，會使用 S3 相容 API，上傳成功後再次從 CDN 讀回確認，才更新文章與圖片清單。未經初始化的舊站仍保留 B2 Native 模式。

**驗收界線：** 公開模板 CI 可以驗證程式邏輯；只有你在私人倉庫提供實際 B2 金鑰、Bucket 和 CDN 後，才能確認真實連線是否成功。
