# 網站初始化與 S3 圖床設定

GitHub Actions 原生表單不支援相依下拉。為了讓選擇供應商後不必再看其他 28 個機房，CMS 改用供應商專屬工作流程，不需要另外架設後台、伺服器或申請 Token。

## 第一步：建立網站基本資料

使用 [公開 CMS 模板](https://github.com/leo72321/CMS-Template-Public) 建立自己的私人倉庫。

進入 **Actions → 網站初始化精靈（基本資料） → Run workflow**，輸入網域（不含 https）、站名、網站簡介與作者，經過驗證後提交網站基本設定。

## 第二步：選擇供應商及該家的機房

在 GitHub Actions 左側工作流程選單，選擇：

- **圖床設定｜01 Backblaze B2**：只列 B2 四個機房，例如 `b2-us-west-004`。
- **圖床設定｜02 Cloudflare R2**：只列一般／EU／US／FedRAMP，另填 R2 Account ID。
- **圖床設定｜03–08**：AWS S3、Wasabi、DigitalOcean Spaces、Hetzner、Scaleway、Akamai／Linode。
- **圖床設定｜09 其他／自訂 S3**：沒列出的供應商或機房，手動填 Region 和完整 API Endpoint。

選對 Bucket 的機房，再填 Bucket 名稱及**完整 CDN HTTPS URL**（例如 `https://cdn.example.com/file/media/`）；系統依所選項目自動確定 S3 Endpoint、Region 與供應商。

**B2 機房必須以 Bucket 詳細資訊的 S3 Endpoint 為準，不能猜測。**

## 第三步：填寫 GitHub Secrets 並驗證

到私人倉庫 **Settings → Secrets and variables → Actions** 建立：

| Secret | 值 |
| --- | --- |
| `S3_ACCESS_KEY_ID` | 所選儲存商的 S3 Access Key ID（B2 一般 Application Key ID） |
| `S3_SECRET_ACCESS_KEY` | 所選儲存商的 S3 Secret Access Key（B2 一般 Application Key） |

再從 **Actions → 圖床連線測試 → Run workflow** 真實上傳測試物件，從 CDN 讀回比對 SHA-256。設定精靈不會自動設定 DNS、CDN Origin 或 Bucket 的公開讀取權限。

不要把金鑰貼在任何工作流程表單、文章、程式碼、公開倉庫或聊天裡；詳細參見 [S3 圖床設定](S3圖床設定.md)。
