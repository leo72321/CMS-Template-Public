# CMS 多語言設定（可選功能）

本公版預設 **關閉** 多語言。沒有 `i18n` 設定、或 `enabled: false` 的既有網站，網址、HTML、索引與前端載入行為皆維持原樣。

## 開啟多語言

在 `site.config.json`：
```json
{
  "language": "zh-TW",
  "i18n": {
    "enabled": true,
    "defaultLocale": "zh-TW",
    "locales": ["zh-TW", "en", "es"],
    "languageSuggestion": true
  }
}
```
請保留其他既有網站設定，不要用上方節錄內容覆蓋整份檔案。多語言設計目前支援繁體中文（台灣）、英文、西班牙文。要新增別種語言，需同步擴充語言登錄表及介面字典。

## 網址與舊站升級

預設語言永遠不加前綴：

- `/`、`/blog/`、`/分類/文章/`：預設語言。
- `/en/`、`/en/blog/`、`/en/category/article/`：英文。
- `/es/`、`/es/blog/`、`/es/categoria/articulo/`：西班牙文。

升級既有網站時不要把原始文章 URL 改為 `/zh-tw/`；原有永久 URL 與 301 規則必須保存。反向相容由原本的 URL Lock 及多語言整合測試維護。

## 建立譯文

預設文章使用原本內容格式，不必填 `locale` 或 `translationKey`。譯文另存一份 Markdown，**每個譯文使用唯一 `uid`**，並新增：

```yaml
uid: my-article-en
locale: en
translationKey: my-article
title: My translated article
slug: translated-article
description: An English explanation
category: english-category
draft: true
publishedAt: 2026-10-25
```

- `translationKey` 必須指向預設語言原稿的 `uid`，同一翻譯群組不能有兩篇相同語言。
- 英文、西文版本可以有不同標題、描述、slug，不必同時發布。仍在草稿的翻譯不會產生公開 URL。
- POST 的 `category`、`tags`、`topic` 要指向**該語言**的分類、標籤與主題 ID。
- 若某語言需要分類，請在 `content/categories` 新增 JSON 分類檔，`id` 與 `slug` 必須匹配該語言的 POST，例如：`{"id":"english-category","slug":"guides","name":"Guides","description":"Guides and examples","indexable":true,"locale":"en","translationKey":"原分類ID"}`。
- PAGE 及 CPT 譯文同樣使用 `locale` 和 `translationKey`。

## 使用者語言

啟用多語言且有 2 種以上語言時，網站可顯示語言切換連結；沒有對應文章譯文時，手動選擇語言可前往該語首頁。不會自動重新導向。

`languageSuggestion: true` 會在**目前內容有實際翻譯**且瀏覽器偏好語言不同時，顯示不阻擋畫面的建議提示；使用者可以切換或繼續瀏覽，選擇會記錄在 localStorage。未啟用多語言的網站不載入提示腳本。選擇直接輸入某語言 URL 時，網站不會覆蓋其選擇。

## SEO 與驗收

- 同一內容不同語言各自擁有獨立 URL、HTML lang、Canonical 和 OG locale。
- 已發布翻譯使用 hreflang 關聯；未發布與 noindex 頁面不應列入 hreflang。
- Sitemap 自動收錄可索引的各語言頁面。
- 發布請執行 `npm run docs:update`、`npm run urls:update`、`npm run verify`。
- GitHub Actions 的「多語言網站情境驗收」會實際開啟三種語言並用 Astro 建置，檢查產物，不會污染正式內容。
