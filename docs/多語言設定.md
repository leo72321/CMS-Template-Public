# CMS 多語言設定（可選功能）

本公版預設 **關閉** 多語言。沒有 `i18n` 設定、或 `enabled: false` 的既有網站，網址、HTML、索引與前端載入行為皆維持原樣。

## 開啟多語言

在 `site.config.json`：
```json
{
  "language": "zh-TW",
  "i18n": {
    "enabled": true,
    "defaultLocale": "zh-TW",
    "locales": ["zh-TW", "en", "es", "ja", "fr", "pt-BR"],
    "languageSuggestion": true,
    "metadata": {
      "en": { "title": "My Brand", "description": "English site description" },
      "es": { "title": "Mi marca", "description": "Descripción del sitio en español" },
      "ja": { "title": "私のサイト", "description": "日本語のページ", "label": "日本語" }
    },
    "messages": {
      "ja": {
        "home": "ホーム",
        "blog": "すべての記事",
        "languagePrompt": "ブラウザの言語は{language}です。切り替えますか？",
        "switch": "{language}に切り替える",
        "stay": "この言語のまま続ける"
      }
    }
  }
}
```
各語言首頁、SEO 標題與簡介可在 `i18n.metadata` 設定獨立站名、description（可選 author），未填時繼承原站設定。新建各國語言頁建議填入當地語言的簡介與翻譯，避免 SEO 描述沿用預設語言。

請保留其他既有網站設定，不要用上方節錄內容覆蓋整份檔案。**語言不是固定三種。** `locales` 可依網站需求自行增減，例如 `["zh-TW","en"]`（兩語）或 `["zh-TW","en","es","ja","fr","pt-BR"]`（六語），不需要再修改公版原始碼。符合 BCP 47 標準即可，例如日文 `ja`、法文 `fr`、德文 `de`、葡萄牙文（巴西）`pt-BR`、簡體中文 `zh-CN`、繁體中文 `zh-Hant-TW` 等；程式會標準化大小寫，網址前綴固定小寫。

`i18n.metadata` 可為每個語言自訂 `title`、`description`、`author` 和語言選單 `label`（省略 label 時由瀏覽器語言資料產生名稱）。`i18n.messages` 可放任意已啟用語言的 UI 翻譯（如上方日文），不需要新增 TypeScript 檔案。公版已有繁中／英文／西班牙文的介面文案可作為方便的範例，**不是語言白名單**；其他語言若沒有填 `messages`，缺少的介面文字會暫以英文回退，正式發布前建議補齊翻譯。

> 啟用新語言不會自動翻譯既有文章；必須提供該語言內容，才會產生對應 SEO 文章。

## 網址與舊站升級

預設語言永遠不加前綴：

- `/`、`/blog/`、`/分類/文章/`：預設語言。
- `/en/`、`/en/blog/`、`/en/category/article/`：英文。
- `/es/`、`/es/blog/`、`/es/categoria/articulo/`：西班牙文。
- `/ja/`、`/fr/`、`/pt-br/`：自選語言入口；例如 `pt-BR` 的網址前綴是小寫 `/pt-br/`。

升級既有網站時不要把原始文章 URL 改為 `/zh-tw/`；原有永久 URL 與 301 規則必須保存。反向相容由原本的 URL Lock 及多語言整合測試維護。

## 建立譯文

預設文章使用原本內容格式，不必填 `locale` 或 `translationKey`。譯文另存一份 Markdown，**每個譯文使用唯一 `uid`**，並新增：

```yaml
uid: my-article-en
locale: en
translationKey: my-article
title: My translated article
slug: translated-article
description: An English explanation
category: english-category
draft: true
publishedAt: 2026-10-25
```

- `translationKey` 必須指向預設語言原稿的 `uid`，同一翻譯群組不能有兩篇相同語言。
- 所有非預設語言版本都可以有不同標題、描述、slug，不必同時發布。仍在草稿的翻譯不會產生公開 URL。
- POST 的 `category`、`tags`、`topic` 要指向**該語言**的分類、標籤與主題 ID。
- 若某語言需要分類，請在 `content/categories` 新增 JSON 分類檔，`id` 與 `slug` 必須匹配該語言的 POST，例如：`{"id":"english-category","slug":"guides","name":"Guides","description":"Guides and examples","indexable":true,"locale":"en","translationKey":"原分類ID"}`。
- PAGE 及 CPT 譯文同樣使用 `locale` 和 `translationKey`。

## 使用者語言

啟用多語言且有 2 種以上語言時，網站可顯示語言切換連結；沒有對應文章譯文時，手動選擇語言可前往該語首頁。不會自動重新導向。

`languageSuggestion: true` 會在**目前內容有實際翻譯**且瀏覽器偏好語言不同時，顯示不阻擋畫面的建議提示；使用者可以切換或繼續瀏覽，選擇會記錄在 localStorage。未啟用多語言的網站不載入提示腳本。選擇直接輸入某語言 URL 時，網站不會覆蓋其選擇。

## SEO 與驗收

- 同一內容不同語言各自擁有獨立 URL、HTML lang、Canonical 和 OG locale。
- 已發布翻譯使用 hreflang 關聯；未發布與 noindex 頁面不應列入 hreflang。
- Sitemap 自動收錄可索引的各語言頁面。
- 發布請執行 `npm run docs:update`、`npm run urls:update`、`npm run verify`。
- GitHub Actions 的「多語言網站情境驗收」會實際開啟超過三種語言並用 Astro 建置，檢查產物，不會污染正式內容。
