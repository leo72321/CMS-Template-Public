# 網站設定說明

根目錄 `site.config.json` 的英文欄位是固定程式名稱，對照如下。

| 欄位 | 中文意思 | 怎麼填 |
| --- | --- | --- |
| `domain` | 正式網域 | `example.org`，不含協定、路徑與斜線 |
| `title` | 站名 | 頁首、SEO 及頁尾共用 |
| `description` | 網站簡介 | 首頁與預設摘要 |
| `author` | 預設作者 | 文章結構化資料使用 |
| `language` | 語言 | 固定 `zh-TW`（台灣繁體中文） |
| `indexable` | 是否允許收錄 | `false` 關閉、`true` 開啟；先換成自己的網域 |
| `productionBranch` | 正式分支 | 預設 `main` |
| `gtmId` | GTM 容器 ID | 留空不載入，如 `GTM-XXXXXXX` |
| `pageSize` | 每頁文章數 | 預設 12 |
| `minArchiveItems` | 彙整頁最低可索引文章數 | 最少 2，不計範例與不收錄文章 |
| `blogIndexable` | 文章總覽是否可索引 | 預設 `true`，仍受 `indexable` 整站開關控制 |
| `blogLegacyPaths` | Blog 舊入口 | 陣列，例如 `["/網站筆記/"]`，舊列表入口 301 到 `/blog/`；舊文章網址 301 到目前分類文章 |
| `relatedArticles.enabled` | 頁底推薦開關 | `true` 才顯示自動延伸閱讀 |
| `relatedArticles.maxItems` | 延伸閱讀總上限 | 0～12，預設 4；扣除正文已連結的站內文章後才自動推薦 |
| `storage.provider` | 圖床供應商 | 初始化精靈可選 B2、R2、AWS S3 或其他 S3 相容服務 |
| `storage.endpoint` | S3 API 端點 | HTTPS 主機，例如 `https://s3.us-west-004.backblazeb2.com` |
| `storage.region` | S3 區域 | B2 例如 `us-west-004`，R2 通常是 `auto` |
| `media.bucket` | 儲存桶名稱 | 新站填實際 S3 Bucket 名稱；未初始化的舊 B2 站沿用原設定 |
| `media.cdnBase` | 圖片公開 CDN 網址 | 新版 S3 必填，例如 `https://cdn.example.com/`；舊 B2 網站可沿用原有前綴 |
| `_說明` | 給人看的註解 | 不影響功能 |

S3 新站的物件 key 為 `網域/分類網址/文章網址/圖片.webp`，預設公開圖片網址是：

```text
https://cdn.你的網域/你的網域/分類網址/文章網址/圖片.webp
```

CDN Origin 必須對應到儲存桶根目錄；若使用 B2 原生公開下載端點，需額外設定 Cloudflare Origin / 路徑改寫，把這個 URL 指向實際的 `/file/桶名/網域/...`。只填 CDN 子網域不代表 DNS 或 Origin 已完成。

沒有 `storage` 設定的舊版 B2 Native 網站則完全保留原先的 `media.cdnBase` 路徑行為。詳見 [初始化精靈](初始化精靈.md)。

## 開放索引

完成正式文案、移除正式內容的 `sample` 範例標記，再將 `indexable` 設為 `true`。範例、`noindex` 頁、門檻不符的彙整頁與後續列表分頁不會進入 Sitemap（網站地圖）。

Cloudflare Pages 非正式分支或無法辨識分支時，自動使用 `noindex` 及 `X-Robots-Tag`（HTTP 索引控制標頭）。也可用 `SITE_PREVIEW=1` 強制預覽。

Cloudflare 正式分支必須與 `productionBranch` 一致。索引指示不是登入權限或保密機制。

`$schema` 指向中文欄位結構檔，支援的編輯器會顯示提示；不會傳給訪客。

## POST 頁尾（全站共用）

| 設定欄位 | 用途 |
| --- | --- |
| `postFooter.tags` | 是否顯示標籤 |
| `postFooter.author.enabled` | 是否顯示作者介紹 |
| `postFooter.author.name/role/bio/photo` | 作者資訊與選填圖片 |
| `postFooter.author.page` | 作者卡連到哪個既有 PAGE（例如 `/about/`） |
| `postFooter.author.linkText` | 作者頁連結文字 |
| `postFooter.blocks[].enabled` | 個別自訂區塊的開關；關閉時資料仍保留 |
| `relatedArticles.enabled/maxItems` | 自動推薦開關及篇數 |

進階元素請見 [POST 頁尾設定與擴充](POST頁尾設定.md)。

## 301 轉址容量／自動退役

| 欄位 | 預設 | 說明 |
| --- | --- | --- |
| `redirectManagement.maxActive` | 1950 | 有效 301 上限；超額淘汰最舊規則 |
| `redirectManagement.overflowAutoPrune` | true | 啟用自動容量保護；關閉時超額拒絕建置 |
| `redirectManagement.agePrune.enabled` | false | 按首次記錄建立日期自動清理，**預設不執行** |
| `redirectManagement.agePrune.days` | 90 | 超過幾個建立日才退役，非最後存取日 |

首次達 1500／1800／1950 條各提醒一次；1950 後每增加一條候選規則都有新提醒。歷史記錄與注意事項見 [轉址容量管理](轉址容量管理.md)。

## XML Sitemap 自動分片（Rank Math 風格）

本 CMS 是 Astro 靜態網站。正式網站的 `/sitemap.xml` 現在是 **Sitemap Index**，不再把所有文章擠進同一份 XML。底下的子地圖依種類分開，單檔達到 `site.config.json` 設定的上限就自動新增下一份：

- `/posts-001.xml`、`posts-002.xml`……：已發佈且允許索引的 POST。
- `/pages-001.xml`、`pages-002.xml`……：獨立 PAGE、首頁、Blog 總覽／分頁。
- `/categories-001.xml`……：達索引門檻且允許收錄的分類列表。
- `/tags-001.xml`……：達索引門檻且允許收錄的標籤列表。

設定方式：在 `site.config.json` 加入或修改下列頂層欄位：

```json
"sitemap": {
  "maxUrls": 200
}
```

預設 **200 個 URL／份**，自行改為 500、1000 等也可以；允許 1–50,000，另檢查未壓縮 XML 是否超過 50 MiB。這是 XML 網站地圖的分片容量，**跟前台文章列表 `pageSize: 12` 完全無關**。

- `robots.txt` 永遠指向 `https://你的網域/sitemap.xml`。GSC 只要提交這個總索引。
- 不允許索引（`noindex`）、草稿、未到公開日的文章不會出現在任何子 Sitemap，也不產生空白子檔。
- POST 的 `lastmod` 只使用文章真正的 `updatedAt` 或 `publishedAt`；其他類型沒有可信更新日期時省略，不寫「今天建置」冒充內容更新日。
- 若整站禁止索引或為 Cloudflare 預覽環境，`/sitemap.xml` 提供**空的 urlset**，不列任何子 Sitemap（與總索引放在網站根目錄，避免搜尋引擎的路徑範圍限制）；`robots.txt` 同時禁止爬取。
- 所有檔案在 Astro **建置時靜態產生**；沒有 JavaScript 轉址、Worker、排程或新增資料庫。

驗收 `npm run verify` 會逐檔核對總索引、每個子 XML、實際可索引網址、重複／漏列、上限、lastmod 與 robots.txt。增刪 POST／PAGE 或修改索引設定後正常建置即可更新，完全不用手動編輯 XML。
